Das Klassenmodell

{{ k.zaehlung.klassen }} Klassen in {{ k.gruppen|length }} Gruppen, zusammen {{ k.zaehlung.zeilen }} Zeilen. Ein Kasten zeigt Datei und Zeilenzahl, die Aufgabe (erster Satz des Modul-Docstrings, aus dem Code gelesen), die öffentlichen Methoden, „beteiligt" (an welcher Aufgabe der Gruppe die Klasse hängt; „Einstieg" = die Klasse, die man ruft) und die Beziehungen: „ruft" nennt die Klasse und womit, „gerufen von" die Gegenseite. Von den {{ k.zaehlung.beziehungen }} Beziehungen sind {{ k.zaehlung.beschriftet }} von Hand beschriftet (auch über die Prozessgrenze, wo es kein import gibt), {{ k.zaehlung.importiert }} sind aus den import-Anweisungen der Dateien gelesen („importiert") — so fehlt keine Kante und keine ist erfunden. Die Gruppen sind eingeklappt; ein Verweis aus der Schrittetabelle klappt die Gruppe von selbst auf.

Die Schichten in einem Satz: Browser → Meshfigurendpunkte (API) → Meshfigurarbeiter startet manage.py meshfigur_fahren → Meshfigurlauf führt die Schritte. Meshfigurhaar, Meshfigurkleidung, Meshfigurfrisur und Meshfigurspeichern rechnen in python14; Meshfigurkette (koerper, gesicht), Meshfigurende (rest, textur) und Meshfigurvorschau rufen über Meshfigurlauf.runner und PipelineProzess den Runner (Meshfigurrunner in python10), der Meshfigurregistrierung auf Meshfigurmodell und Meshfigurabstand stützt. Die Figur-Seite (Meshfigurgenesis, G9netzbereiche, G9reglerableitung, G9restmorph) liefert Käfig, Bereiche, Ableitungen und den Eigenmorph.
